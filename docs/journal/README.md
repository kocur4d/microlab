# Engineering journal

This journal preserves Microlab's engineering lessons, decisions, and enough context to resume work after time away.

## When and where to write

- Write a note only on explicit request, such as "add a journal note" or "journal this".
- Use one Markdown file per learning session, named `YYYY-MM-DD-short-topic.md` with the session date and a short, lowercase, hyphenated topic.
- Review the current session and existing entries before writing. Update an entry when extending the same session; use a distinct topic filename for a separate session on the same date. Avoid duplicating existing notes.
- Keep notes concise and technical. Use short sections and bullets, with code snippets only when they clarify a lesson or decision. Omit empty sections and avoid transcripts.
- Distinguish verified results (including relevant checks) from assumptions and planned work. Do not invent details that the session did not establish.

## Suggested entry format

```markdown
# YYYY-MM-DD: Short topic

## Work and lessons
- What we worked on and learned.

## Decisions
- Decision and the reasoning behind it.

## Results
- Verified: what worked, what failed, and supporting checks.

## Open questions and assumptions
- Unresolved questions or explicitly unverified assumptions.

## Next step
- The next concrete action needed to resume.
```

When resuming, read the latest dated entry first and check the current project state against its recorded status. If multiple sessions share that date, use their content to establish the relevant stopping point.
